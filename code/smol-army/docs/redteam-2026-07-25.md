# Red-team round, 2026-07-25 — four attack surfaces vs the ch9 deliverables

Protocol: four independent sessions (one per surface: scorer / data composition /
independence / cost accounting), each briefed with a neutral claim list and file
paths only — no expectations, no narrative. Every charge was required to carry an
executable check; checks were run against this repo's committed files. All key
findings were independently replicated by the editor before disposition.
Dispositions use the three-level scheme: OVERTURN / NARROW / CAVEAT.

The pre-registered numbers in results/report.md stand as registered throughout;
everything below is post-hoc and labeled as such.

## Charges sustained, with dispositions

**R1. Clean-subset "reversal" was largely a scorer parsing artifact — OVERTURN.**
The post-hoc clean-math split (army −2.3pp [−4.0, −0.7], commit 7b084b7) counted
answers like `1200**`, `} 522`, `10**` (markdown/boxed residue around the correct
value) as zeros — a failure mode one-sided against small reasoning models; the
frontier never emits such residue. Relaxed numeric extraction: frontier 1.0000,
army_vote 0.9967 (single real miss: 12786 vs gold 12806), self_consistency
1.0000; paired diff −0.33pp, CI touching zero. Combined with R5 (two template
families ⇒ effective df ≈ 2), the −2.3pp reversal is retracted: on clean math
all arms saturate and the family is uninformative in BOTH directions. The pilot
had fixed the same bug class for `%`; `**` and `}` survived it. The audit needed
auditing.

**R2. Pre-registered SC cost-parity clause silently violated — VIOLATION +
NARROW.** prereg.md requires self_consistency's k be adjusted post-pilot so its
USD/query matches army_vote within ±10%, recorded in CHANGES.md. Never done: k
stayed 5; actual SC/vote cost ratios math 0.21, mmlu 0.37, code 0.77. All
"same-budget self-consistency" labels are retracted; restated honestly: SC ran
at ≤ army cost and still matched or beat the army everywhere except mmlu — which
strengthens, a fortiori, the "teaming ≈ sampling" critique, but the registered
control design was not executed as registered.

**R3. Code-family vote is mechanically degenerate — OVERTURN (mechanism).**
majority() tallies exact strings and returns the first sample on ties; extracted
code strings essentially never collide, so army_vote(code) always returned the
round-robin's first sample — qwen's single sample. The 93.7% is a single-model
single-sample score; 4 of 5 calls bought nothing. On math/mmlu, tallies were
also un-normalized (`20` / `20%` / `**20**` split votes). The code-family
"teaming" narrative is retracted; the surviving (and cheaper) claim: a single
small model's single sample sat 2.3pp under the frontier on a saturated,
likely-contaminated 100-item HumanEval+ slice with no statistical power to
resolve differences ≤5pp (87/100 items concordant; prereg's own verdict:
inconclusive, not tie).

**R4. "mmlu_pro, stratified by category" was actually business/law/psychology
only — NARROW.** fetch_data.py pooled the first 2000 rows of a category-blocked
test split (12,032 rows); the pool contained 3 of 14 categories (STEM: zero),
verified by question-id lookup (50/50/50). Per-category deficits: business
−9.3pp, psychology −10.0pp, law −25.3pp; 3-cluster bootstrap widens the CI to
[−25.3, −9.3] (degenerate: min/max of cluster means). Every "knowledge QA" claim
narrows to "knowledge recall in business/law/psychology". The math sampling bug
had a registered twin; this one wasn't registered until now.

**R5. Cluster structure invalidates iid CIs beyond the registered note —
NARROW.** Full-math 3-cluster bootstrap: +18.2pp [−4.0, +59.3] — crosses zero
(cluster means −0.7 / −4.0 / +59.3). "~3 template families" needs an operational
definition (script's literal-template count prints 17; the 50-variant blocks
give 3); recorded here. Gold answers are also clustered (dice block: 24/50 gold
= "25"; remora: 16/50 = "10"), so majority voting harvested a modal-gold bonus
that is inseparable from genuine correction in this design. The math family is
retired as evidence in both directions: ambiguous template + saturation +
answer clustering + scorer residue.

**R6. Ledger is a list-price simulation, not billed cost — NARROW (wording) +
CAVEAT.** ledger.py prices tokens from prices.toml and never reads OpenRouter's
returned cost; demo usage shows actual billed = 1.187× table for gpt-oss
(routed-provider premium), so army-side costs are underestimated ~19% and the
claim "actual dollars billed" is retracted in favor of "list-price × tokens".
Also: 12.6% of real spend ($0.70 of $5.58 — purged SC rows, truncation reruns,
one item billed 3× at the 4096 cap with score 0) is in the ledger but outside
every reported USD/query figure; under full-ledger accounting SC-vs-vote cost
parity on code is exact ($0.000526 vs $0.000529). Both accountings are now
disclosed; report figures remain marginal-cost-of-final-configuration.

**R7. Frontier arm ran with observed zero reasoning tokens — NARROW + CAVEAT.**
Demo usage shows completion_tokens_details.reasoning_tokens = 0 on all frontier
calls; main-run frontier median completion ≈ 115 tokens. The frontier arm is
therefore "GPT-5.6-terra at its API-default (observed: zero) reasoning effort"
— an undisclosed configuration knob that both lowered its bill and plausibly
its accuracy. Budget remedies were also asymmetric (qwen raised to 8192 after
truncations; frontier kept 4096 and item mmlu-1830 hit the cap 3× for 0).
All frontier cost/accuracy claims carry this caveat. (This also retires the
earlier "unbeatable defense" that hidden reasoning tokens made the frontier
bill honestly expensive — there were no reasoning tokens to bill.)

**R8. Extraction layer is unauditable — CAVEAT + text correction.** runs.jsonl
stores the extracted answer, not the raw model output; ANSWER_RE takes the
FIRST match, so a reasoning model that writes "ANSWER:" mid-think can be
truncated invisibly, and rescore.py cannot reach behind extraction. The book's
ch7 claim "raw outputs on disk" is corrected to "extracted answers on disk".
Loss bound unquantifiable — which is the point.

**R9. Degenerate [0,0] "tie" verdicts — NARROW.** debate/division ran the
100-item math slice that happens to exclude the ambiguous block entirely; both
arms and frontier scored 1.000 there, bootstrap resamples were all zero, and
stats.py printed CI [+0.000,+0.000] → "tie". Zero-variance ties are artifacts
of slice selection + no degenerate-CI guard; those two math rows carry no
equivalence information.

**R10. Cost ratios are procurement-sensitive — CAVEAT.** gpt-oss at demo-observed
routed prices already moves SC/vote to 0.89; any provider ≥$0.05/$0.20 flips
"SC cheaper". OpenAI Batch/Flex half-price (the natural way to buy a 400-item
offline eval) moves code vote/frontier from ~1/5 to ~2/5 and mmlu to 0.78.
Frontier unit price itself was verified against community aggregators, not
OpenAI's page (open item for the author's billing console).

**Minor sustained:** mmlu format-residue zeros exist but are negligible
(~3/450 rows; −14.9pp → ≈−14.2pp). 2/2/1 round-robin weighting (5 % 3) gave
qwen double weight in vote arms — disclosed; math vote cost is 87% qwen
thinking tokens, and reordering the model list alone moves math vote cost
between $0.00119 and $0.00195.

**Attacked and held:** the ambiguity finding itself (50/50 items match the
"more likely (as a percentage)" wording, 49/49 exact-4× relative readings,
d20 variant self-consistent under the absolute reading); pairing/alignment in
report.py; ledger row-level arithmetic vs prices.toml; SC arm model identity
(1200 rows × 5 gpt-oss calls, zero qwen leakage); code scoring replay (160
rows, zero mismatches); no fabricated rows.

## What survives, restated with the narrowing applied

1. On a saturated, likely-contaminated 100-item HumanEval+ slice, a single
   small open model's single sample scored 93.7% vs the frontier's 96.0%
   (design cannot resolve ≤5pp; prereg verdict: inconclusive) at list-price
   cost ratios of roughly 1/25 per call (1/5 was the 5-call vote's cost).
2. On business/law/psychology knowledge recall, small models lag the frontier
   by roughly 9–25pp depending on category; teaming does not close it.
3. The math family is retired as evidence in both directions.
4. Nowhere in this design did true teaming (voting/debate/division) show a
   measured benefit over a single small model's samples at equal or lower cost.
5. Every cost claim is list-price × tokens, procurement-sensitive, with the
   frontier at an observed zero-reasoning configuration.
